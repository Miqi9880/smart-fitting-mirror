## Miqi9880 · FLUX 推理服务与联调

企业 FR-VTO-05／06。负责老师服务器的模型进程、GPU 和脱敏联调记录，后端接入由 [#5](https://github.com/Miqi9880/smart-fitting-mirror/issues/5) 负责。环境、固定权重和样例推理已经完成，直接复用。

**环境**　沿用 `/data_new/smart-fitting-mirror/` 下的 FLUX 独立环境（Python 3.10、PyTorch 2.8 + CUDA 12.8、Diffusers 0.37.1）及已校验权重。启动前核对共享 GPU 占用，按 UUID 选择可用卡。服务只绑定服务器回环，联调使用同主机或由负责人建立 SSH 转发。

1. 按[内部推理协议](interfaces/local-model-draft.md)实现健康检查与单件上衣推理，用已有预处理、固定权重和经评估的提示词。模型未就绪、任务忙碌、超时都按约定返回。只收校验过的图片字节，日志只记脱敏指标。
2. 先用已获准的 CG 模特和一件上衣确认真实 PNG，再和 #5 走已有游客会话、上传、生成、轮询和下载。分开记录冷启动、热推理和上传到结果可见的端到端时间、输出尺寸和显存。对照企业 5–15 秒目标如实记录差距。
3. 做一次占用中拒绝新任务及一次超时／断连验证。检查旧结果不会覆盖任务终态；记录推理何时实际结束、任务槽何时可复用，停服务后确认 GPU 占用恢复。客户端收到超时只证明请求结束。
4. 准备和验收 [#60](https://github.com/Miqi9880/smart-fitting-mirror/pull/60) 最新提交的 API 35 像素回归，向 #6 提供必要固定姿态或素材 ID。FLUX 联通后，按设备和本人可用时间做镜子端到端确认；真实拍照上传另行取得明确授权。

**交付与验收**　交付脱敏启停／复现说明、至少一张获准样例生成结果的受控存储记录，以及冷／热／端到端耗时和超时／显存复核。应用或镜子未测的阶段单列。重点是固定一条能复现的路径。

**提前完成后**　按老师实际反馈安排 3D 单件继续验证，关注抬臂、前伸、肩袖／领口、实际帧率和稳定性；再决定扩款。Depth／对齐／分割与 8–12 小时长稳保留为企业验收缺口。
