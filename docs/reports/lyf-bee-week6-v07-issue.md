# [T02/T05] V07 横竖画幅对照：先保持合成人体像素比例，再验证衣服形变

关联：[#15](https://github.com/Miqi9880/smart-fitting-mirror/issues/15)、#3（T02 人体视觉）、#6（T05 服装渲染）· 证据：[周报第 8 节](lyf-bee-week6.md#8-模拟器实操验证补充)（作者的模拟器观察与离线复现）。2026-10-16 负责人审阅补正：保留现象，修正原先“所有非 3:4 画幅都存在渲染缺陷”的归因。

## 环境

| 项 | 值 |
| --- | --- |
| 模拟器 | Medium Phone，API 37.0 |
| 后端 | 本地 Uvicorn `127.0.0.1:8000`（App 内填 `http://10.0.2.2:8000`） |
| 输入 / 服装 | SyntheticVisionSource（合成样例）；`upper_blue` |
| 场景 | 静止人体（暂停），画幅由第二个下拉框切换 |
| App 版本 / 提交号 | 据 Issue #15 记录为 `main @ 49cafe4` |

## 复现步骤

1. 仓库根目录启动模拟后端：`python -m backend --host 127.0.0.1 --port 8000 --mode success`
2. 模拟器安装 App 并连接本地服务，选择蓝色休闲上衣（`upper_blue`），进入合成样例
3. 场景选「静止人体」，暂停固定一帧
4. 画幅选「竖图 480×640」→ 衣服贴合正常
5. 画幅切「横图 640×480」→ **衣服被横向拉宽，比例不对**

离线复现（不需要模拟器）：重放 `TryOnView` 绘制数学——归一化像素中心映射 `0.5 + v*(size-1)` + 四点投影（等价 `Matrix.setPolyToPoly`），素材 `upper_blue`、静止人体姿态，两种画幅各渲一张，量衣服 alpha bbox 宽高比。`FitCenter` 是单一 `min` 缩放，不引入拉伸。

## 预期 / 实际

**验收目标**：保持同一人体的像素比例，仅改变画幅或显示布局时，衣服不应额外拉伸，且仍贴合相应肩髋。当前切换会改变合成关键点的像素比例，尚不是该目标的有效对照。

**实际**：

| 画幅 | 衣服 alpha bbox | 宽高比 | 相对素材（0.827） |
| --- | --- | --- | --- |
| 竖图 480×640 | 236×284 | 0.831 | 1.005×，正常 |
| 横图 640×480 | 315×213 | 1.479 | **1.789×，横向拉宽** |

## 已确认的输入变化与归因边界

`SyntheticScene.sample()` 在两种画幅中提供相同归一化点，`SyntheticVisionSource.emit()` 只替换图像宽高。按 `0.5 + v*(size-1)` 映射后，**人体目标四边形本身就改变了比例**；四点投影会随之改变衣服形状：

| 四边形 | 宽 × 高（px） | 宽高比 |
| --- | --- | --- |
| 素材锚点（600×800 画布） | 299.5 × 559.3 | 0.536 |
| 姿态锚点 · 竖图 480×640 | 143.7 × 255.6 | 0.562 |
| 姿态锚点 · 横图 640×480 | 191.7 × 191.6 | 1.000 |

固定归一化点时，肩宽为 `0.30*(width-1)`，肩到髋高度为 `0.40*(height-1)`。两种输入的比例变化为：

```
横图目标四边形宽高比 / 竖图目标四边形宽高比 = (639/479)^2 ≈ 1.7796
```

该值不是衣服 alpha bbox 相对素材的比值，也不是任意摄像头/素材的通用公式。负责人核对了输入与映射代码；上表 alpha bbox 与对比图片是作者的离线测量，本轮未独立重绘或复测。

## 影响范围

- 已发现当前合成样例切换画幅时，人体目标四边形及衣服一起变宽。
- 不能据此认定所有非 3:4 输入或真实摄像头都有渲染缺陷；真实关键点会根据图像内容重新归一化。
- V01–V06 保留作者已报告的结果；V07 仍待以保持人体比例的输入验收。
