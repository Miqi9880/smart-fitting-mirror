# [T05] V07 横图画幅下衣服被拉宽 —— TorsoWarp 锚点四边形长宽比不匹配

关联：#6（T05 服装渲染）· 证据：[周报第 8 节](lyf-bee-week6.md#8-模拟器实操验证补充)（模拟器实测 + 离线复现）

## 环境

| 项 | 值 |
| --- | --- |
| 模拟器 | Medium Phone，API 37.0 |
| 后端 | 本地 Uvicorn `127.0.0.1:8000`（App 内填 `http://10.0.2.2:8000`） |
| 输入 / 服装 | SyntheticVisionSource（合成样例）；`upper_blue` |
| 场景 | 静止人体（暂停），画幅由第二个下拉框切换 |
| App 版本 / 提交号 | 待补（创建 Issue 前回填） |

## 复现步骤

1. 仓库根目录启动模拟后端：`python -m backend --host 127.0.0.1 --port 8000 --mode success`
2. 模拟器安装 App 并连接本地服务，选择蓝色休闲上衣（`upper_blue`），进入合成样例
3. 场景选「静止人体」，暂停固定一帧
4. 画幅选「竖图 480×640」→ 衣服贴合正常
5. 画幅切「横图 640×480」→ **衣服被横向拉宽，比例不对**

离线复现（不需要模拟器）：重放 `TryOnView` 绘制数学——归一化像素中心映射 `0.5 + v*(size-1)` + 四点投影（等价 `Matrix.setPolyToPoly`），素材 `upper_blue`、静止人体姿态，两种画幅各渲一张，量衣服 alpha bbox 宽高比。`FitCenter` 是单一 `min` 缩放，不引入拉伸。

## 预期 / 实际

**预期**：切换画幅只改变图像尺寸与显示布局；衣服相对人体的形状不随画幅改变而拉伸。

**实际**：

| 画幅 | 衣服 alpha bbox | 宽高比 | 相对素材（0.827） |
| --- | --- | --- | --- |
| 竖图 480×640 | 236×284 | 0.831 | 1.005×，正常 |
| 横图 640×480 | 315×213 | 1.479 | **1.789×，横向拉宽** |

## 根因

失真来自锚点四边形**长宽比不匹配**；四点投影（`TorsoWarp.points` → `setPolyToPoly`）本身是忠实的：

| 四边形 | 宽 × 高（px） | 宽高比 |
| --- | --- | --- |
| 素材锚点（600×800 画布） | 299.5 × 559.3 | 0.536 |
| 姿态锚点 · 竖图 480×640 | 143.7 × 255.6 | 0.562 |
| 姿态锚点 · 横图 640×480 | 191.7 × 191.6 | 1.000 |

归一化锚点按 x、y 分别映射到 `(width-1)`、`(height-1)`，同一组归一化四边形的像素宽高比与**画幅长宽比成正比**；投影把素材四边形拉成目标四边形的形状。合成样例下：

```
拉伸倍数 = 画幅长宽比 ÷ 素材画布长宽比 = (4/3) ÷ (3/4) = 1.778   （实测 1.789×，差值为边界取整）
```

## 影响范围

- 所有非 3:4 画幅；机制与输入来源无关（真实摄像头下倍数由真人姿态四边形与素材四边形之比决定）。
- 不影响 V01–V06（竖图 3:4 下全部通过）；不影响坐标换算与测量（归一化坐标本身正确）。

## 修复候选（待评审）

1. **渲染侧补偿**（`feature-tryon`）：目标四边形按素材画布长宽比做等比修正后再投影；
2. **约定侧统一**：数据源/素材约定统一长宽比基准（如姿态四边形按固定人体比例定义）。

## 边界

本 Issue 由合成样例验证得出；合成几何不能证明真实人体识别精度、真实试衣效果或设备性能。
