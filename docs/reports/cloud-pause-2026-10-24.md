# COS费用反馈与真实调用暂停

2026-10-24负责人转达：haiyangniu191-design发现COS向Aidge传图产生费用，已禁用COS，当前腾讯COS→阿里Aidge链路暂停。此为成员／负责人报告，不是本轮读取云账单后的独立核验；已验证的历史真实结果继续有效，但不能作为当前服务仍可用的证明。本轮不恢复COS、不上传图片、不提交真实生成。

[腾讯云流量说明](https://cloud.tencent.com/document/product/436/53863)将存储与外网下行流量分别计费，公网获取对象可产生下行流量；是否抵扣取决于实际资源包。仅知道50GB容量额度，不能推断外网流量、请求和模型调用均免费。具体费用与异常流量需对照已脱敏账单，不要求再次发请求“验证是否收费”。

当前代码AidgeCosProvider将图片上传COS，再把签名URL交给Aidge。[当前VirtualTryOn官方接口](https://help.aliyun.com/zh/aidge/api-aidge-2026-04-28-virtualtryon)要求ModelImageUrl／ClothImageUrl为公网HTTP(S)地址。现有接口不能直接换成电脑本地路径；没有据此证明支持Base64。更换为其他存储／图床仍需核对授权、访问、清理及费用，不能未经评估就宣称免费或自行迁移。

已有内部TryOnProvider边界接收人物字节、服装本地路径、服装类型及超时预算，返回标准图片；不把COS暴露给Android。因此未来自部署模型可通过同机文件或受控内网服务消费图片，无需继续经COS转阿里。模型、权重和服务尚未就绪，当前不新增模型专用公共接口，也不宣称模型已经替代API；GPU／服务器和网络成本单独评估。

当前安排：

1. 真实Aidge/COS适配保留并暂停，默认MOCK和端侧实时预览继续用于软件开发；模拟结果明确标记。
2. 后端先增加真实调用总开关与关闭时的明确不可用状态：在供应商上传／提交前阻断，不自动换成模拟成功。关闭场景使用FakeProvider证明外部调用为零，不用真实账号测试。
3. 增加匿名调用记录与统计：功能／提供方／模型、真实或模拟、创建／实际提交／缓存复用、成功／失败、耗时。幂等重试不重复记提交，取消不等于供应商已停止计费。
4. 费用分成模型调用、存储、流量／请求；没有适用费率或账单时保持未知，不填0元。载荷字节不是腾讯账单实测下行量，估算需注明来源、单位、地域／时间与假设，不能把120秒超时预算称费用预算。
5. 之后继续企业P0视频库／规则召回和其他独立软件任务，不等待模型微调，不重做已通过的首次真实闭环。恢复付费链路需负责人明确确认预算和授权；不布置成员购买或充值。

首个开关／统计增量不等于完整费用后台、按日月硬限额与预算告警均完成。原文优先级差异及剩余验收见[需求对应表](../requirements-traceability.md)。
