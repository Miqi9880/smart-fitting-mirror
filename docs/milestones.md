- [ ] T01 完成 Android 骨架与共享类型。

## 阶段一：设备到位后确认可行性

- [ ] 记录 Android 型号、SoC、RAM、系统版本、大屏分辨率与方向。
- [ ] 记录摄像机型号、SDK、Android 支持情况和 RGB/深度规格。
- [ ] 在目标 Android 设备稳定读取 RGB 与深度数据。
- [ ] 验证 RGB/深度对齐、镜像方向、设备拔插与重连。
- [ ] 输出人体关键点，让一件上衣素材跟随肩部和躯干移动。
- [ ] 验证手臂遮挡所需的数据，记录技术限制。
- [ ] 获取一张原始单帧，经后端触发一次试衣生成并显示结果。
- [ ] 记录端侧实际帧率、推理耗时、云端生成耗时与失败情况。
- [ ] 根据真机结果，与老师确认课程范围和验收要求。

## 阶段二：核心试衣流程

- [ ] 完成站位引导、服装选择、实时跟随和基本遮挡。
- [ ] 完成拍照/上传提示、生成等待、失败处理和结果对比。
- [ ] 实现摄像头不可用、跟踪丢失、网络超时后的恢复流程。
- [ ] 实现结束会话与自动超时清理。
- [ ] 测试不同身高、轻微转身、抬手与前后移动。

- [ ] 接入少量规范服装素材，注明来源。
- [ ] 实现基础服装管理和调用统计。
- [ ] 按标签返回至少 5 条相关视频候选并支持播放。
- [ ] 完成安装说明、接口说明、测试记录和已知限制。
- [ ] 在目标设备完成连续运行、异常恢复和端到端演示。

## 文档指标与待确认范围

原需求给出实时镜面建议 20 FPS 以上、最低可接受 15 FPS；高清生成 5–15 秒为首轮目标，需按实际服务、网络与输入规格验证，不能视作已保证的性能。

原需求还提出 8–12 小时稳定性测试。课程是否严格执行该时长，以及内容后台和费用统计的必做范围，需要与老师确认；原文不同章节的优先级并不完全一致。
