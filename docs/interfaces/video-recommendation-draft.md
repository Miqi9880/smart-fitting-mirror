# 服饰视频推荐输入输出草案

2026-10-24任务拆分依据：原文FR-VID-01／02／05、7.4、12.1。本页是负责人给出的协作草案，不是已发布API；当前HTTP合同仍0.3.0。首个后端增量先做独立数据校验／内容库／规则函数；添加HTTP路径前须在同一接口PR更新OpenAPI、样例、版本与Android类型，不能两端各自定义。

## 视频内容与上下文

| 数据 | 首轮约定 |
| --- | --- |
| 内容标识 | 稳定video_id、标题、是否上架 |
| 播放资料 | 播放URL或受控本地文件、封面、时长；不得把人物生成图当封面默认保存 |
| 内容标签 | 品类、风格、颜色／场景标签及可选关联garment_id；与当前服装元数据／用户选择匹配 |
| 来源 | 来源与授权说明、示例／测试标记、可播放状态；无来源的测试URL不能说成已获授权可播 |
| 推荐请求 | 当前已选服装ID列表＋用户主动选的标签；游客会话，不需要身份档案、人体原图或生成图 |
| 推荐结果 | 稳定视频ID、标题／封面／播放资料、匹配维度及标签来源；候选去重，仅返回上架内容 |

先用结构化标签召回和可解释规则，至少在品类、风格、颜色或场景一个维度相关。需要5条候选时应有足够的相关内容；不足时明确数量／空态，不重复凑数、不自动返回不相关内容。测试可使用合成元数据，但必须与可播放的授权内容分开记录。

规则标签来源可分服装元数据、用户选择、模型语义、测试数据。没有模型输出时不能标成AI语义完成；FR-VID-03仍保留后续显式理解、JSON校验、失败降级和预算条件。推荐列表检索本身不上传人像或自动触发收费服务。

## 安卓消费与验收顺序

1. yyyrrrxxx先用FakeVideoRepository和程序生成／获准测试短片验证卡片、横竖视频适配、暂停／下一条／返回、可控音量；不依赖真实云生成或镜子。
2. 退后台、切换内容、返回试衣和结束会话时停止／释放播放器及挂起加载；保留当前试衣设置，不重开生成任务。播放失败有可读提示和返回路径，不白屏。
3. 后端接口PR定稿后接真实目录，沿用现有鉴权、网络和临时会话；不写死未发布接口，也不把模拟元数据说成已取得5条可播放内容。
4. 至少5条相关、确实可播放的自有／授权内容到位后，才验收完整推荐播放闭环。内容来源确认由负责人协调，缺内容只阻塞这一验收，不阻塞规则与播放器的软件交付。
