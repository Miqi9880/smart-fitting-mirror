## 开发依赖

1. 负责人合并接口基线，建立 Android 骨架及纯数据类型。
2. 三人分别以普通 RGB 摄像头、合成关键点、模拟生成服务开发。
3. 使用相同数据类型进行第一次联调，替换模拟视觉源。
4. 拿到真机后接入深度并测性能。RGB 演示不能当作深度或企业设备验收通过。

后端 HTTP 模拟服务和素材整理可在 Android 骨架完成前开始；Android 模块依赖骨架，不各建一个长期独立 App。

## 当前决策与保留项

| 项目 | V0.1 决策 |
| --- | --- |
| Android 方向 | 原生 Kotlin 为初始工程方向；构建工具版本及 minSdk 在工程任务中固定，拿到设备后复核 |
| 后端语言与模型 | 实现者提出选择，负责人记录；不得改变公共 HTTP 合同 |
| 视觉接口 | 进程内调用；JSON 仅用于样例/验证，不逐帧上传 |
| 坐标 | 竖正、未镜像的原图归一化坐标；显示层负责一次镜像 |
| 深度与 mask | 可为空，明确上报能力；不伪造测距或遮挡成功 |
| 初期功能 | 单人、正面、一类上衣、选择/预览/生成/对比/清理 |
| 后续功能 | 视频推荐、后台管理、深度遮挡；不阻塞首次 RGB 联调 |

每轮只设一个可演示目标。暂无课程日期，不编造截止时间；[任务清单](tasks.md) 使用依赖顺序安排。负责人汇总老师待确认的问题，并在得到答案后更新基线。
