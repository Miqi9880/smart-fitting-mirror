# 分工与模块接口约定

本文是设计约定草案，字段类型、模块目录和技术栈在首次联调前共同确定。

## 硬件与人体视觉

负责人：待填写（当前项目发起人负责该方向）。

输出摄像头帧、人体关键点及置信度、人体分割结果、对齐后的深度信息、站位与跟踪状态。负责摄像头权限、启动停止、重连、帧时间戳及原始单帧获取。

需明确每份数据的分辨率、坐标系、镜像与旋转状态；深度数据需说明单位、无效值和对齐方式。

## 实时试衣效果与主工程集成

负责人：待填写。

消费视觉结果，完成服装位置、尺寸、形变、遮挡与画面合成；维护 Android 入口、试衣页面、服装选择和对比交互。主工程只保留一个摄像头采集入口，不重复打开设备。

人体前景分割不能直接区分手臂与躯干。视觉与渲染负责人需要共同验证遮挡所需数据，渲染负责人实现最终合成。

## 后端与 AI

负责人：待填写。

负责服装目录、云端模型代理、生成任务、缓存、调用统计、标签推荐和对应 Android 网络/结果模块。后端不向客户端返回云端 API 密钥。

云端输入使用服务要求的原始照片和服装条件；带实时叠加的预览截图应与原始单帧分开，不能默认混用。

## 首次联调前确定的三个接口

| 接口 | 需要约定的内容 |
| --- | --- |
| 视觉结果 | 帧与结果时间戳、图像尺寸、关键点名称/坐标/置信度、分割格式、深度单位、跟踪状态、数据释放责任 |
| 服装素材 | 服装编号、缩略图、实时预览素材、云端参考图、类别、标签、对齐参数；两种素材可不同 |
| 生成任务 | 输入照片及服装编号、任务编号、等待/运行/成功/失败/取消状态、结果地址、超时与错误信息 |

镜像、旋转、屏幕缩放分别由哪一层处理，必须明确，避免重复变换。视觉处理结果要能匹配对应摄像头帧，避免数据不同步导致漂移。

## 会话结束

- Android 主流程触发统一结束事件，清除选择与画面状态。
- 视觉模块释放或重置本次跟踪数据，按待机策略处理摄像头。
- 网络模块取消客户端等待，尽可能请求取消服务端任务；服务端不支持取消时，结束会话后不再显示迟到结果。
- 各模块清理自己的临时图像、缓存引用与会话数据，并验证超时退出同样生效。

测试与文档由各模块负责人编写；集成负责人汇总整机验证结果。
