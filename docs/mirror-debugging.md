# 镜子无线远控与后端调试

2026-10-22由Miqi9880现场执行，电脑协助操作；现场与真人验证不转交其他成员。

## 无线调试与投屏

镜子开启开发者选项／无线调试，与电脑同网。在“使用配对码配对”弹窗取得配对地址，在无线调试主页面取得连接地址；二者端口通常不同。官方步骤见[Android ADB无线连接](https://developer.android.com/tools/adb#connect-to-a-device-over-wi-fi)。在电脑已有ADB的终端中操作，替换以下占位文字：

```powershell
adb pair "镜子IP:配对端口"
adb devices -l
```

按提示在终端输入当前配对码；不将配对码、设备序列号或个人局域网地址提交Git。现代ADB可通过mDNS自动连接；若设备列表没有目标镜子，再执行`adb connect "镜子IP:连接端口"`。列表应显示目标镜子的model与`device`状态。

通过[官方scrcpy](https://github.com/Genymobile/scrcpy/blob/master/doc/connection.md)打开投屏控制：

```powershell
scrcpy -s "adb devices中镜子的序列号" --no-audio --max-size=1600 --max-fps=30
```

这只打开屏幕投控，不会替App选择摄像头。配对成功后配对弹窗可以关闭，无线调试保持开启；之后需要重连时以当前设备列表／连接端口为准。

## 通过ADB转发访问电脑后端

本轮电脑后端仍监听127.0.0.1:8000，无需为调试开放校园网入站端口。后端终端保持运行；在另一个终端执行：

```powershell
adb -s "adb devices中镜子的序列号" reverse tcp:8000 tcp:8000
adb -s "adb devices中镜子的序列号" reverse --list
```

镜子App填**http://127.0.0.1:8000**并连接。这里127.0.0.1指镜子上的转发入口，依赖当前ADB连接；不是说镜子能直接访问电脑的回环地址。断线／重启后先恢复ADB并检查转发。App进程重启后目前仍需重新填写服务地址；后端仍需启动。模拟器才使用10.0.2.2。

先点“合成样例”检查目录和素材加载。连接服务不会开启相机；“拍摄并上传生成”才上传单帧，当前生成仍是MOCK，不要将模拟结果当成真实模型输出。

## Gemini2当前彩色通道

本次实物确认为Gemini2（VID2BC5/PID0670，固件1.4.92），主机安装的厂家Demo应用版本为2.0.6。旧App默认通道0得到绿色画面；0.3.3新增“相机通道”按钮，本次重新连接后的**ID5**已实测显示彩色并输出关键点／上衣跟随。不要依据前向／背向标签或本次ID推定所有设备的RGB角色。

在相机未运行时选择通道不会开启采集；准备真人测试后点“RGB摄像头”。运行中切换会停止旧输入、释放旧帧，再按新ID绑定。显式通道不可用会报错，不自动切到其他相机；旋转保留选择，进程重启不保存ID。

厂家Demo在实体屏彩色预览正常时，本次scrcpy／截图显示为黑色预览区，不能仅据远控黑屏判断相机故障。本轮Demo占用USB后部分Camera2通道消失，退出Demo未全部恢复，负责人重新拔插摄像头USB后恢复3个通道。若再遇到类似现象，先退出占用相机的应用、核对当前通道，再由现场负责人处理相机连接；不修改固件或主机供电参数。
