## 全组目标与当前事实

交付同一个 Android App：选衣／组合预览 → 主动拍未叠加的原图 → 后端生成 → 前后对比 → 结束清理。**主线继续接外部试衣 API，负责人自己的预训练模型微调独立进行，完成后再接。** 详见 [总体方案](delivery-plan.md) 与 [模型路线](model-strategy.md)。

## 环境与验证

Android 沿用 Android Studio、JDK 17／21、SDK 35 和 Wrapper；后端沿用已验证的 Python 3.12。外部 API 路线不要求 GPU／CUDA；负责人训练环境独立，按所选模型另定，不影响成员环境。本轮不强制 Unity、NDK 或 Blender。

从负责人取得本地课程商品素材包，在仓库根目录执行：

```powershell
python tools/install_studio_assets.py "素材包.zip"
python tools/install_studio_assets.py --check
python -m backend --port 8000 --catalog-db data/catalog.sqlite3
```

模拟器填 `http://10.0.2.2:8000`；获准调试的普通安卓手机可用 `adb reverse tcp:8000 tcp:8000` 后填 `http://127.0.0.1:8000`。reverse 只转发后端端口，不会自动开启或接管摄像头。手机不是硬性前置条件，目标镜子最终另验收。

按改动跑适用检查：后端 `python -m pytest backend/tests -q`；合同／文档 `python tools/check_contracts.py`；Android 在 android 目录运行相关模块 `testDebugUnitTest`／`lintDebug` 和 `:app:assembleDebug`。纯文档不要求完整 Android 构建，渲染或相机行为需实际操作／对应仪器验证，不能只交几何测试。提交前 `git diff --check`。

本地默认生成仍是 MOCK，其烟雾检查用 `python -m backend.smoke --url http://127.0.0.1:8000`。历史四模式 Android 回归依赖旧 ID 时，使用 `--catalog-profile regression` 和独立数据库；真实提供方验收另用真实测试，不能套用要求 is_mock=true 的检查充数。
