## 模型就绪后再接入

预期结构如下，当前不提前实现第二条生成路由或切换按钮：

```text
同一个 Android App → 公共后端 → 外部试衣 API（当前主线）
                            → 微调模型推理服务（模型就绪后再接）
离线训练／微调 → 导出已验证权重 → 推理服务
```

后续接入前至少具备：

1. 可复现推理：人体图＋服装图可产生结果，提供启动命令、依赖版本、权重版本／来源、所需预处理和支持品类；训练不放进用户生成请求里。
2. 效果与资源说明：保留原权重与微调后在同一组未参与训练样例上的对照，写明成功／失败、实际耗时和显存，不把静态叠加当模型输出。
3. 服务边界：与后端共同约定内部输入输出、超时／取消／排队、结果读取和清理；遮罩或姿态图等额外输入由模型接入侧处理。
4. 主线回归：已有外部 API 和 MOCK 均可继续运行；任务创建后固定使用的生成方案，状态／幂等／清理不互相串用。公共合同有变化时按现有接口流程另开 PR。

达到条件后，由负责人和后端维护人在独立 PR 中接入；初期可用后端配置选方案，是否需要 App 选择入口另行确认。是否能在镜子本机推理也须实测，当前不作承诺。
