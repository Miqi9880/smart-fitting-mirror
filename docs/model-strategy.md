# 试衣生成路线：外部 API 主线与独立微调探索

决策更新：2026-10-21，依据项目负责人本次确认。本页规定工作范围，不表示真实 API 或双引擎已实现；当前仓库生成仍为 MOCK。

## 当前主线

haiyangniu191-design 负责接一个外部试衣 API，同时维护公共后端和 Android 网络层。现有 App 的上传、任务轮询、结果对比和会话清理继续共用。Miqi9880 保留硬件／人体视觉、公共接口与审阅合并职责；lyf-bee、yyyrrrxxx 的渲染／交互分工不变。

主线第一步是确定一个可调用的提供方：输入图要求、支持品类、认证／额度、耗时、错误和取消行为、结果有效期及人像处理要求。条件具备即可完成一次真实生成，再接入 App；没有配置时明确阻塞，继续可独立完成的公共服务工作，不把 MOCK 改名为真实结果。

首轮真实生成先支持单件上衣。裤子和帽子继续已有实时二维预览；提供方是否支持这些品类，须有实际接口和验证证据后再扩展。实时预览不是逐帧调用生成 API。

## 负责人独立探索

Miqi9880 计划下载已有预训练试衣模型，再用适合的数据微调。仅部署现成权重不算已训练；模型选择、数据、GPU／显存、训练环境和耗时均尚未确认。

探索不作为本周共同验收、主线接入或其他成员任务的前置条件；不要求其他成员配置训练环境、准备数据或等模型结果，也不设置“本周必须训练成功”。先跑通原模型推理，再按实际资源决定微调规模。

训练使用独立虚拟环境和本地／受控工作目录。公共后端当前 Python 3.12 不要求训练栈也用相同版本，应按所选模型的实际依赖确定；不为探索直接改主项目 requirements 或 Gradle。人像数据、权重、检查点、凭证和生成图不提交普通 Git；来源与版本用文字清单记录。

## 模型就绪后再接入

预期结构如下，当前不提前实现第二条生成路由或切换按钮：

```text
同一个 Android App → 公共后端 → 外部试衣 API（当前主线）
                            → 微调模型推理服务（模型就绪后再接）
离线训练／微调 → 导出已验证权重 → 推理服务
```

后续接入前至少具备：

1. 可复现推理：人体图＋服装图可产生结果，提供启动命令、依赖版本、权重版本／来源、所需预处理和支持品类；训练不放进用户生成请求里。
2. 效果与资源说明：保留原权重与微调后在同一组未参与训练样例上的对照，写明成功／失败、实际耗时和显存，不把静态叠加当模型输出。
3. 服务边界：与后端共同约定内部输入输出、超时／取消／排队、结果读取和清理；遮罩或姿态图等额外输入由模型接入侧处理。
4. 主线回归：已有外部 API 和 MOCK 均可继续运行；任务创建后固定使用的生成方案，状态／幂等／清理不互相串用。公共合同有变化时按现有接口流程另开 PR。

达到条件后，由负责人和后端维护人在独立 PR 中接入；初期可用后端配置选方案，是否需要 App 选择入口另行确认。是否能在镜子本机推理也须实测，当前不作承诺。
