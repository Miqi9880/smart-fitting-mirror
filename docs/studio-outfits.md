## 安装运行

向负责人取得 **smart-fitting-mirror-studio-assets-20261021-v3.zip**（透明运行包），不要混用带51张JPEG的原图来源包。运行包SHA-256：

```text
f39f47e6b3eb43840783966dca26fe6b6a28685977ecf5c1f4cbab8c3f6626aa
```

在仓库根目录使用现有 Python3.12：

```powershell
python tools/install_studio_assets.py "smart-fitting-mirror-studio-assets-20261021-v3.zip"
python tools/install_studio_assets.py --check
python -m backend --port 8000 --catalog-db data/catalog.sqlite3
```

安装器先核对全部文件、尺寸、RGBA和哈希再写入，拒绝未知路径／重复／缺失文件；缺包API返回503 ASSET_NOT_INSTALLED。运行包不能替代APK，队友还需构建本次Android版本。模拟器填 http://10.0.2.2:8000；普通安卓手机沿用ADB reverse或已配置的局域网地址。

目录上限升到100。SQLite revision2→3仅补新内置ID，不恢复之前删除的五件、不覆盖已编辑条目；刻意清空的目录保持空。旧回归四件会一次性替换，所有迁移保留自建条目，仅按余量添加，重新打开不重复回填。CLI与游客衣柜均在满额时允许更新／删除、拒绝新增。正常与 regression 数据库继续分开。

## 怎么试

1. 连接服务，再点“合成样例”；连接本身不打开相机。真人验证须用户主动选 RGB。
2. 可以选择“上衣＋一种下装＋帽子”，也可以“连衣裙＋帽子”。选连衣裙自动移除上衣和下装；选上衣或下装会退出连衣裙，长裤／半裙／短裤互相替换。
3. “加入搭配”“移除本类”“清空搭配”继续可用；旋转保留选择，退出清理 Bitmap 和会话。缩略图同时最多3个加载，避免51件全量解码造成瞬时内存峰值。
4. 长裤按髋／膝／踝分腿；半裙保持整片裙摆，连衣裙另外对齐肩部和躯干；短裤只覆盖髋到膝之间，不套长裤到脚踝。帽子用双耳；长裙需要可靠腿部，短裙／短裤不要求踝点。缺少所需点时隐藏对应品类，不使用历史点。

长度字段 hem_ratio、各类别源控制点与互斥规则见 [HTTP接口](interfaces/backend.md)。这些是初始二维标定，不是量体、三维布料或精细遮挡。OBJ实验只替换上衣层；整套搭配不套躯干近似深度面。上衣仍每次一件，拉链外套图片是闭合商品图，不能把覆盖内搭称为已支持叠穿。

生成仍只接受单件 garment_id，当前仍为 MOCK；连衣裙／裤子／半裙／短裤／帽子暂只实时预览。外部模型的支持品类由后端成员实测后接，不随新图片自动宣布完成。
