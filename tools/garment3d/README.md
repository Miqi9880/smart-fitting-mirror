# 单件 T 恤动作修形样件

本工具独立验证蓝色 `studio_blue_tee` 的站立、抬臂、前伸与转身。v1 抬臂时出现大三角形拉伸，v2 重建网格，v3 修正袖口、透明裂口及面片碰撞后，用户又从俯视指出袖根窄了一圈。v4 补肩部截面体积并增加俯视与截面回归；不能只用正面远景或穿模采样验收外观。详见[肩部体积记录](../../docs/reports/garment3d-shoulder-2026-11-04.md)、[袖身衔接记录](../../docs/reports/garment3d-junction-2026-11-04.md)及[历史动作记录](../../docs/reports/garment3d-motion-2026-11-04.md)。

## 当前实现与范围

- 以原始官网 PNG 作正面 UV 参考，按名义短袖结构建立中性 T 姿态；商品图的平铺轮廓不能直接作为人体 A 姿态的物理裁片。
- 使用受边界约束的三角剖分和均匀内部采样，保留领口、下摆、两袖口四个开口；默认 2,154 顶点、4,188 三角面。
- 统一 5 骨骼、躯干/锁骨/颈/髋椭球及上/下臂胶囊体。显示人台与碰撞代理使用同一参数。
- 先从中性姿态生成站立，再做肩部抬臂和前伸。修形包括姿态引导、XPBD 距离/柔性弯曲及代理碰撞，衣身和下摆能移动。领口及圆形袖口边界固定到骨骼目标，代表近似的加强边；不把整个躯干固定住，也不模拟袖口自身变软。
- 袖笼与衣身用平滑过渡连接。除顶点外，在肩部/腋下加入边中点及面中心接触约束，避免顶点在手臂外、连接面却切入手臂。
- 肩部保留前后厚度，袖根到袖口逐渐收拢，避免先把衣身椭圆压扁再接圆袖管。加强边仍为原来的圆形袖口，并未把整件衣服放大。
- 3D 布面使用不透明材质，由真实网格开口限定袖口和领口；正面 UV 边界移入原图不透明区域，避免继承二维去背景的假裂口。纯蓝袖子改取中央布面纹理，减少平铺照片的固定阴影；不适用于直接复用花纹或标志袖子。
- **动作在本机 CPU 预计算**，浏览器播放这些修形网格。它不是浏览器逐帧布料求解，也不是 Garment3DGen 复现；未校准真实面料、重力垂坠、自碰撞或真人姿态。
- 转身将站立人台和衣服一起旋转，支持 ±180° 和循环；这验证前后体积/材质与绑定，不包含转身惯性引起的布料飘动。
- 动作切换先沿原片段退回站立，再进入新动作；骨骼与衣服使用同一帧，避免身体先跳到新姿态而衣服还在旧姿态。
- 背面/侧缝借用正面中央布面纹理作近似，以保持颜色衔接；没有真实背面参考，不能代表商品背面结构或图案。

原 PNG 不改像素，GLB 中嵌入字节与原图摘要一致。品牌图片、带纹理 GLB、动作数据和截图留在忽略目录 `.local/`；源码和不含图片的验证入库。没有下载神经网络权重、打开摄像头、上传照片或调用付费 API。

## 本机运行

环境：Node.js 22+、Python 3.10+、支持 WebGL 的浏览器；不需要 Blender 或训练 GPU。在本目录执行：

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm test
npm run test:motion
python -m unittest discover -s test -p "test_*.py"
npm run build
npm run test:sample
python server.py --port 8022
```

打开 <http://127.0.0.1:8022/>。只监听本机回环地址，Three.js 使用本地 npm 依赖；Ctrl+C 停止服务。界面提供四个动作、循环、转身角度、正/侧/背视角、拖动旋转、人台/线框开关。「细节」放大检查袖笼、肩缝及腋下；「俯视」直接检查肩部截面，不能只用全身远景验收。

`npm run build` 先生成基础 GLB，再预计算动作，需要负责人已有的私有素材：

```text
backend/assets/studio/manifest.json
backend/assets/studio/studio_blue_tee.png
```

构建固定核验已检查图片的 SHA-256 与尺寸，素材更换后必须重新核对 UV。依赖锁定于 npm 官方注册源。

没有素材的协作者仍可运行 `npm test`、`npm run test:motion` 和 Python 路由测试。CI 也运行这三项；动作回归直接使用代码生成的网格，不需要品牌 PNG、云账号或 GPU。

## 输出与真实性

```text
.local/blue-tee.glb  # 中性 T 姿态网格、原 PNG 与骨架；不附带 v1 错误的纯骨骼动画
.local/source.png   # 原图逐字节复制
.local/sample.json  # 来源、限制、几何/文件摘要
.local/motion.bin   # 183 个顶点位置样本，约 4.51 MiB；不含真人数据
.local/motion.json  # 片段边界、几何/数据摘要、求解参数和逐帧质量记录
```

基础 GLB 与动作文件是分开的。浏览器加载 GLB 后组合其材质/网格，再应用动作样本；直接在其他查看器打开 GLB 看到的是 T 姿态。前端会校验动作版本、顶点/字节数、帧布局和模型几何摘要，拒绝混用旧模型与新动作。

183 个样本为站立 1 帧、抬臂 91 帧、前伸 91 帧。回程及循环反向遍历同一片段，60 FPS 样本间插值；转身复用站立网格。**页面帧率是渲染这些预计算数据的桌面帧率，不能作为实时布料求解或镜子性能证据。**

## 验证

- 有限坐标、非退化网格、有效 UV/法线/骨骼权重、缝合面朝向、四个完整开口。
- 中性袖口共面、半径一致且不随求解扭成尖角；边中点接触能发现两端均在胶囊体外的穿插；原 PNG 像素不变，GLB 不使用透明裁切模拟开口。
- 中性和完整抬臂的左右肩部均检查实际三角面截面：距中心 20–30 cm 的六个切面，最薄处不小于外侧袖管厚度的 97%（容许剖分采样差异）。这是名义模板尺度，不能当作真实商品尺寸；本项只约束已检查姿态，不代表任意动作的体积保持。
- 站立→动作→返回/切换/循环的播放器时序；不用跨姿态网格直接混合而让身体跳变。
- 固定动作全 183 帧检查名义网格边长变化；长度大于 8 mm 的边统计 P99 和最大值，薄侧缝的厚度边不作为布料伸长指标。
- 每帧采样全部顶点、三角面中心和边中点，与同一人台代理检查相交；这不是任意姿态、真实体型、自碰撞或完整连续三角碰撞证明。
- 回归限值：P99 < 1.10、最大边长比 < 1.30、代理相交深度 < 2 mm；抬臂终点最大边长比 < 1.01。单位为名义模板坐标，不是实测商品或真实布料性能。
- 独立 Khronos glTF Validator 要求零 error、零 warning，验证嵌入原 PNG 字节；原图非 POT 尺寸是保留源图产生的信息项。
- 动作文件与模型摘要、帧布局及文件摘要一致；本地服务不提供目录列表、`.env` 或路径穿越读取。

Android 已提供离线人台实验入口，见下节；目标镜子与真人 3D 驱动尚未验证。后续还需姿态/体型适配、相机投影和镜像裁切、真人遮挡、运行时修形及目标镜子帧率验证；此工具不替代 #6 的现有正式渲染修复，也不关闭企业 P0 验收任务。

## Android 软件接入（第一阶段）

App 首页点「3D 人台样件（实验，不开启摄像头）」。它在本机 WebView 中渲染同一 GLB 和预计算动作，提供四动作、六视角、旋转/缩放、人台/线框开关；**当前仍为合成人台，未把该 3D 衣服穿到真人身上**。不依赖电脑预览服务器、后端或外部 API。进入前停止首页感应；退出后不会自动重新开相机。普通游客会话不插入该独立实验页，保留原会话超时/清理路径。

负责人已有完整 `.local/` 资源和 `npm ci` 安装的 Three.js 时，正常 Android 构建会将运行页面、选定的本地 JS、Three.js MIT LICENSE、模型/原图/动作自动复制到 **build 生成目录**后打入 APK。构建核对 GLB、PNG、动作摘要及几何版本，拒绝混用资源；无需把品牌图片和二进制提交 Git。

```powershell
# 先在本目录准备 npm 依赖和私有模型/动作（前述 npm run build）。
cd ../../android
./gradlew.bat :app:assembleDebug
# 显式复现没有私有素材的协作者/CI 构建：
./gradlew.bat -PincludeGarment3d=false :app:assembleDebug
```

没有私有资源/依赖时 App 仍可构建，但实验入口显示明确的缺包提示；不是自动下载，也不会用空画面冒充三维成功。CI 显式关闭该私有包，其 APK 不包含蓝色品牌样件；负责人提供的本机 APK 单独验证。页面更新需重建/覆盖安装 APK，改电脑服务器不会更新已安装的离线包。

后台停止动画，恢复不计入暂停的墙钟时间；退出销毁 WebView/渲染资源；渲染进程异常退出提供重新加载。原图/动作资源只允许固定 APK 来源，拒绝网络回退、文件/内容 URL、下载与相机/定位权限请求，没有暴露原生 JS 接口。功能与验证边界详见 [Android 接入记录](../../docs/reports/android-garment3d-2026-11-04.md)。

## 批量素材的成本

相同版型换色可复用网格、骨架与动作修形资料，仍需各色纹理/裁切/UV 及效果质检。袖长、领型或宽松程度变化需要调模板与重新验证；长裤、裙装等品类需要对应结构。当前只验证这一件，**批量导入尚未实现**。

例如 10 个相同版型各 3 色，可按 10 套版型和 30 套纹理组织；不同品牌图片裁切、袖子摆放与遮挡会增加导入成本。精确商品尺寸及面料行为还需要企业提供多视图、尺寸或 CAD/面料资料。

## 代码

- `template.mjs`：名义中性网格、边界约束剖分及原图 UV。
- `texture-uv.mjs`：只读原图 alpha，将正面边界 UV 移至不透明布面，不编辑图片像素。
- `rig.mjs`：统一骨架、动作与人台参数。
- `cloth.mjs`：姿态约束修形和代理碰撞。
- `bake-motion.mjs`：可独立测试的 CPU 预计算与逐帧记录。
- `motion-player.mjs`：经站立衔接的片段时序。
- `viewer-lifecycle.mjs`：逐视图暂停/恢复/终止的时钟与渲染循环。
- `viewer.mjs`：实际 GLB/动作数据预览，动画与人台同步。
- `quality.mjs`：边长与代理表面采样检查；`test/`：几何、时序、动作、导出和路由回归。

约束方程参考 [XPBD 原论文](https://matthias-research.github.io/pages/publications/XPBD.pdf)，并不声称复现论文的完整布料系统或其他项目的质量。品牌素材没有开放再分发许可声明，发布/商业使用仍需企业确认素材权利。
