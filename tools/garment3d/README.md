# 单件 3D T 恤样件

用现有 `studio_blue_tee` 正面素材，验证「近似服装模板 + UV 纹理 + 骨骼」是否值得继续投入。此工具独立于 Android 正式渲染链路，不改变 APK、接口或其他成员正在做的工作。

## 已实现的效果

- 真正有前后体积的网格，领口、下摆、左右袖口保持开放；侧缝和肩缝连接，边缘向薄缝收拢。
- 原始官网 PNG 不改像素，直接映射正面；背面及侧缝使用明确标注的近似蓝色材质。
- 5 个骨骼，袖子随肩部运动；自然站立、抬臂、前伸及循环抬臂。
- 本地浏览器加载**实际导出的 GLB**，支持旋转、缩放、正侧背面、隐藏合成人台、线框和 GLB 下载。
- 模板、网格校验、导出和预览代码入库；含品牌图片的 GLB、PNG、截图留在被忽略的 `.local/`。

这是手工参数化的近似模板，**不是 Garment3DGen 运行结果、AI 单图重建或厂家 CAD**。没有下载模型权重、调用云 API、打开摄像头或上传真人照片。

## 运行

需要 Node.js 22+、Python 3.10+；CPU / 支持 WebGL 的浏览器即可，不需要训练 GPU。使用 npm 官方注册源的锁定依赖，不需要 Blender。

在本目录执行：

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm test
python -m unittest discover -s test -p "test_*.py"
npm run build
npm run test:sample
python server.py --port 8022
```

打开 <http://127.0.0.1:8022/>。服务只绑定本机回环地址，使用本地 Three.js 依赖，不依赖 CDN；按 Ctrl+C 停止。

`npm run build` 需要负责人本机已有的私有素材包：

```text
backend/assets/studio/manifest.json
backend/assets/studio/studio_blue_tee.png
```

缺少素材的协作者仍可运行 `npm test` 和 Python 路由测试。`npm run test:sample` 专门校验本机生成的 GLB，不能在没有素材的干净检出中直接运行；CI 只做不依赖品牌图片的模板和路由校验。

生成文件：

```text
.local/blue-tee.glb   # 约 2.17 MiB，包含原始品牌 PNG
.local/source.png    # 原图逐字节复制
.local/sample.json   # 来源、限制、顶点数、文件与几何摘要
```

`build-sample.mjs` 先验证素材清单 SHA-256，再输出 GLB。嵌入图像保留原字节；导出测试再校验一次嵌入图像的摘要。发布或商业交付前仍需企业确认品牌素材使用权限；没有把官网图片声明为开放许可。

## 验证与实际边界

当前默认细分为 5,202 顶点、10,048 三角面。自动校验覆盖：

1. 有限坐标、非退化三角面、有效 UV、单位法线和归一化骨骼权重。
2. 无非流形边、缝合面朝向一致、恰好四个开放边界环。
3. 抬臂时袖子顶点发生位移、躯干不随整件刚体移动、恢复站立时回到原点位。
4. 独立 Khronos glTF Validator 检查实际 GLB，要求零 error、零 warning；原图非 2 的幂尺寸是保留源图导致的信息项，不是错误。
5. 本地服务不提供仓库目录列表、`.env` 或路径穿越读取。

浏览器验证应看：正面、侧面、背面、两种动作、循环、线框、人台开关和窄窗口布局。页面帧率是当前桌面浏览器的观测值，受后台节流和硬件影响，**不能认定 Android 镜子达到企业实时帧率指标**。

尚未解决：

- 单张正面图无法核验背面图案、侧面结构、真实厚度和尺寸；当前补全都只是近似。
- 照片原有阴影和褶皱已烘在纹理里，未生成物理材质、法线或真实运动褶皱。
- 骨骼蒙皮不等于布料仿真；大幅抬臂仍可能拉伸、腋下夹折或穿模，不应当作最终质量。
- 合成人台不代表真实人体体型；未加入真人姿态、手臂前后遮挡、人体分割、深度和体型自适应。
- 未接 Android 3D 渲染器，未更换现有正式的实时试衣方案，未做镜子性能/真人贴合验收。

## 衣服变多后的成本

不是每个 SKU 都需要从零建模，也不能承诺每件衣服自动处理后就合格。按**版型模板**管理，而不是按颜色复制一套模型：

| 新增内容 | 可复用 | 仍需处理 |
| --- | --- | --- |
| 同一版型、不同颜色或印花 | 网格、骨架、蒙皮和动作 | 新纹理、图片裁切/UV 对齐、颜色与边缘复核 |
| 同类 T 恤但袖长、宽松量或领型变化 | 工具、部分拓扑和绑定规则 | 调模板参数、必要时改网格，重验领口/袖口和动作 |
| 衬衫、长裤、半裙、连衣裙 | 导出、查看器、来源登记、部分通用校验 | 各自的结构模板、骨骼权重和遮挡规则 |
| 精确展示商品尺寸/面料垂坠 | 通用管线 | 真实尺寸、多视图或品牌 CAD、面料参数、体型适配和仿真验证 |

例如 30 个 SKU 如果实际是 10 个相同版型各 3 色，目标是维护约 10 套模板及 30 套纹理资料，而不是 30 次从零雕模。**每色仍有导入和质检成本**；不同品牌的图片裁切、袖子摆放及遮挡会增加处理量。

当前脚本只选择已验证的蓝色 T 恤，**尚未实现批量换色导入**。下一步应先补一个配置化导入层：模板 ID、图片裁切/UV、背面资料、版型参数、骨架规则和验收记录；验证同款其他颜色确实能复用后再批量接入。先建立少量代表版型，比给全部素材逐件做高精度模型更适合本项目。

## 代码定位

- `template.mjs`：不依赖图片的模板、细分、缝合、UV、蒙皮和合成姿态。
- `build-sample.mjs`：来源校验及 glTF 2.0 二进制导出，PNG 保持原样。
- `viewer.mjs` / `index.html` / `style.css`：GLB 加载与交互预览、明确展示样件限制。
- `server.py`：仅允许指定路径的本机静态服务。
- `test/`：独立于 Android 和后端服务的几何、导出与路由测试。

## 与企业要求的关系

该样件探索服装随身体/手臂运动的后续质量路径；无法替代 FR-VTO-02/04 所需的真实人体信息和遮挡处理，也不改变端侧/本地实时链路的性能要求。先评估质量提升，再决定是否做端侧集成。照片级 AI 换装和此处的交互式 3D 路线仍是两条不同的实现。
